# speedrun.fog

The `/speedrun` page (navbar item "Speedrun", formerly the `speedrun.fog` tab of `/stats`, whose `?tab=speedrun` URL redirects to it, whatever else the query holds) is a speedrun.com style game page: game header card, category pills, Set Seed and Random Seed subcategories, ranking table, side column with game stats and recent runs, in SpeedFog's colors. Set Seed replays put several runners on the same seed, which makes their times comparable across runs; Random Seed ranks blind runs only.

Each category (a pool) has two boards, **Set Seed** and **Random Seed**, plus a **Deathless** filter. Computed in `services/speedrun_service.py`, served by `api/stats.py`.

**Which runs are counted.** A participant with status FINISHED in a race that has a seed and is itself FINISHED, whose user is not banned. Races flagged `exclude_from_stats` stay out, except Daily Seeds and event races (qualifiers and playoff races), which count. Public and private races both count. Pools whose config `type` is `training` never appear. Finished solo sessions in `speedrun` or `set_seed` mode (`TrainingSession.mode`) also count, as run type `solo`, under the same pool and layer-count rules; practice sessions never do. A run is `blind` unless it is a Set Seed replay (a race with `Race.set_seed` or a `set_seed` session), the runner having known the seed beforehand. Only seeds at the pool config's current `layers_count` count (a seed with another `total_layers` stays out), which stands in for "the current version of the pool": seeds generated before the fixed layer counts of May 2026 varied in depth (Standard ran from 17 to 38 layers), so most of them drop out, though an old seed that landed on the current count still counts. Changing a pool's layer count restarts its board, like a new game version on speedrun.com; to keep the old board viewable, the operator adds the old count to the pool TOML's `[display] archived_layers` and rescans the pool (see Archives below). A pool whose config has no `layers_count` keeps every seed. Requiring a finished race keeps a running Daily Seed or an open qualifier out until it ends, so the board never reveals the deaths or weapons a running daily hides.

**What each board counts.**

| Board       | Counts                                                                                                                                                       |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Set Seed    | Every counted run: blind and replay runs, of every run type (`race`, `daily`, `event`, `solo`).                                                              |
| Random Seed | Blind runs only: runs whose seed the runner did not know beforehand (not `Race.set_seed`, not a `set_seed` session). Empty when a category only has replays. |

A run's `blind` flag is exposed on every row, so a Set Seed board can mark which runs were blind. The Deathless filter (`deathless=true`) keeps only runs of races with the deathless option (`Race.deathless`) and so never includes solo runs. It combines with either board. The default boards include deathless races.

**Archives.** A pool can declare older layer counts worth keeping a board for in its `config.toml`, `[display] archived_layers = [25, 22]` (racing-only: the seed generator never reads it). `_normalize_pool_config` stores it as a list of ints under `archived_layers` on `Pool.config`; a value that is not a list gives `[]` and non-int items (booleans included) are dropped one by one. A counted run whose seed's `total_layers` is in that list (and is not the current count) belongs to the category `<pool>@<layers>` (e.g. `standard@25`, served by `GET /api/stats/speedrun/standard@25`); a seed at any other non-current count stays out, as before. An archived category is always retired, is named `<Pool display name> (<layers> layers)` and is released at its earliest seed at that count; it is listed only while it has counted runs.

**Categories.** One per pool with at least one counted run at its current layer count, plus the archives above: enabled pools by `sort_order` (pools without one last), then disabled (retired) pools in the same order. A category's `released_at` is its earliest seed at the current layer count (any seed without `layers_count`); the History list opens with it ("Boss Rush was released"). The category key of a board is the pool name, or `<pool>@<layers>` for an archive; a recent run's `pool` carries that key.

**Ranking.** A board is a category, a `sub` (`set` or `random`), the Deathless filter and a set of run types. Each player keeps their best run (lowest IGT, the earliest on a tie). Equal IGT shares a rank and the next rank skips (1, 2, 2, 4). With obsolete runs requested, every run of the board is listed by time and the runs that are not their player's best carry no rank. The record history lists, in date order, each run strictly faster than every earlier one; the web side words it like speedrun.com's history list (a new holder "set a new record time" and shows the gain on the previous record, a holder beating their own record "improved their time"). A recent run's place is its place on its category's Set Seed board (all run types, Deathless filter off): 1 + the number of other players whose best there is strictly faster.

**Record seed.** A board response carries `record_seed`: the seed of its first ranked row (the record) and how many runs of the board, obsolete ones included, are on that seed. `null` on an empty board.

**Weapon** (the "Route" column, after speedrun.com's Elden Ring boards). The combo held for the most ticks over the run (summed `zone_history` weapon ticks, base ids), the same id coercion as `/weapons`. Runs from before weapon tracking have none. It is decoded only for the rows a response returns, never for the whole run list.

**The page.** `/speedrun` (header "Speedrun", `web/src/routes/speedrun/+page.svelte`, state in `web/src/lib/speedrun.ts`) mirrors its state into the URL so a board can be shared: `pool`, `sub=random` (Set Seed is the default and stays out), `deathless=1`, `types`, `obsolete=1`, `view`. The old `sub=any|deathless` values read as Set Seed. A board shows the category pills, then the "<Category> - Subcategories" segmented control (Set Seed / Random Seed), then the **WR seed band** (a gold-tinted strip: "WR seed" chip, the record's seed linking to its race or day, its time, the holder, a Blind or Replay chip and "N runs" from `record_seed`; absent when `record_seed` is null), then the toolbar. Filters lists Races, Daily Seeds, Event races, Solo runs, "Deathless only" and "Show obsolete runs". The **Run column** (Blind or Replay chip) shows on the Set Seed board only. A seed links through `speedrunSeedHref` (the race or the day; plain text for a solo run, which has no race page yet). A recent run of the side column reads "Blind" or "Replay", plus " · Deathless" for a deathless run, then its weapon.

**OBS overlay.** The "OBS overlay" button of the board toolbar opens a settings window that builds the URL of `/overlay/speedrun/<pool>`, a transparent leaderboard for an OBS Browser Source in the style of the race leaderboard overlay (badge in place of speedrun.com's flag, name template kept). It shows the board on screen, personal bests only (never obsolete runs): the category, `sub=random` for Random Seed (Set Seed is the default and stays out), `deathless=1` for the Deathless filter and the `types` filter, under the page's own parameter names. The settings window builds the URL from the board currently shown (its `sub` and `deathless`), and the overlay reads them to fetch the matching board. `top` rows (default 3) stay fixed from first place; `cycle` rows (default 3) page every 6 seconds through the players after them, up to rank `until` (default 20, players tied at that rank included); `player` (a Twitch username, matched whatever its case, prefilled with the viewer's own) pins that player's row at the bottom, set apart, with a gold time. A pinned player already in the top gets the gold time in place instead, and never also shows in the cycle; a player without a run on the board gets no row. Default values stay out of the URL. The overlay refetches the board every 5 minutes (every 30 seconds until a first load succeeds), so a new personal best shows once the stats cache has refreshed (up to about half an hour, as on the tab). The row split lives in `speedrunOverlayRows` (`web/src/lib/speedrun.ts`).

**Endpoints.** `GET /api/stats/speedrun` returns the categories, the run and player counts and the five most recent runs. `GET /api/stats/speedrun/{category}?sub=set|random&deathless=<bool>&types=<race,daily,event,solo>&obsolete=<bool>` returns one board, its record history and its record seed; `sub` defaults to `set` and anything else is 422, `types` must be a non-empty subset of the four (422 otherwise) and a category without counted runs answers 404.

**Cache keys.** Both endpoints sit behind the stats cache; the counted run list itself is cached once (`speedrun:runs`, light columns only) and every board key (`speedrun:board:<category>:<sub>:<deathless>:<types>:<obsolete>`) derives from it. A board is cached as its serialized JSON bytes rather than a response model: with obsolete runs shown it lists thousands of rows, and one bytes object adds nothing to garbage-collection passes nor needs serializing on each hit.
