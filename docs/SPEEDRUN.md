# speedrun.fog

The `/speedrun` page (navbar item "Speedrun", formerly the `speedrun.fog` tab of `/stats`, whose `?tab=speedrun` URL redirects to it, whatever else the query holds) is a speedrun.com style game page: game header card, category pills, Set Seed and Random Seed subcategories, ranking table, side column with game stats and recent runs, in SpeedFog's colors. Set Seed replays put several runners on the same seed, which makes their times comparable across runs; Random Seed ranks blind runs only.

Each category (a pool) has two boards, **Set Seed** and **Random Seed**, plus a **Deathless** filter. Computed in `services/speedrun_service.py`, served by `api/stats.py`.

**Run modes.** `RunMode` (`normal`, `speedrun`, `set_seed`) is set when a race or a solo session is created and never changes. The migration `c3a9d71e5b24` backfilled `Race.mode = speedrun` for every race that was finished at deploy, had a seed, was neither a Daily Seed nor an event race and was not excluded from stats (their `exclude_from_stats` is untouched); every other existing race and session is `normal`. Known gap: a community race still running at deploy stays `normal` and does not count. Race and session responses (`RaceResponse`, `RaceDetailResponse`, `TrainingSessionResponse`, `TrainingSessionDetailResponse`) carry it as `mode`.

**Which runs are counted.** A participant with status FINISHED in a race that has a seed and is itself FINISHED, whose user is not banned. Among community races only those whose `Race.mode` is `speedrun` or `set_seed` count (a `normal` race never does; `exclude_from_stats` is no longer read here); Daily Seeds and event races (qualifiers and playoff races) count in any mode. Public and private races both count. Pools whose config `type` is `training` never appear. Finished solo sessions in `speedrun` or `set_seed` mode (`TrainingSession.mode`) also count, as run type `solo`, under the same pool and layer-count rules; `normal` sessions never do. A run is `blind` unless it is a Set Seed replay (a race or session whose mode is `set_seed`), the runner having known the seed beforehand. Only seeds at the pool config's current `layers_count` count (a seed with another `total_layers` stays out), which stands in for "the current version of the pool": seeds generated before the fixed layer counts of May 2026 varied in depth (Standard ran from 17 to 38 layers), so most of them drop out, though an old seed that landed on the current count still counts. Changing a pool's layer count restarts its board, like a new game version on speedrun.com; to keep the old board viewable, the operator adds the old count to the pool TOML's `[display] archived_layers` and rescans the pool (see Archives below). A pool whose config has no `layers_count` keeps every seed. Requiring a finished race keeps a running Daily Seed or an open qualifier out until it ends, so the board never reveals the deaths or weapons a running daily hides.

**What each board counts.**

| Board       | Counts                                                                                                                                                              |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Set Seed    | Every counted run, blind and replay, of every run type (`race`, `daily`, `event`, `solo`), except runs on a seed an admin excluded from Set Seed.                   |
| Random Seed | Blind runs only: runs whose seed the runner did not know beforehand (mode is not `set_seed`, for races and sessions alike). Empty when a category only has replays. |

A run's `blind` flag is exposed on every row, so a Set Seed board can mark which runs were blind. The Deathless filter (`deathless=true`) keeps only runs of races with the deathless option (`Race.deathless`) and so never includes solo runs. It combines with either board. The default boards include deathless races.

**Archives.** A pool can declare older layer counts worth keeping a board for in its `config.toml`, `[display] archived_layers = [25, 22]` (racing-only: the seed generator never reads it). `_normalize_pool_config` stores it as a list of ints under `archived_layers` on `Pool.config`; a value that is not a list gives `[]` and non-int items (booleans included) are dropped one by one. A counted run whose seed's `total_layers` is in that list (and is not the current count) belongs to the category `<pool>@<layers>` (e.g. `standard@25`, served by `GET /api/stats/speedrun/standard@25`); a seed at any other non-current count stays out, as before. An archived category is always retired, is named `<Pool display name> (<layers> layers)` and is released at its earliest seed at that count; it is listed only while it has counted runs.

**Categories.** One per pool with at least one counted run at its current layer count, plus the archives above: enabled pools by `sort_order` (pools without one last), then disabled (retired) pools in the same order. A category's `released_at` is its earliest seed at the current layer count (any seed without `layers_count`); the History list opens with it ("Boss Rush was released"). The category key of a board is the pool name, or `<pool>@<layers>` for an archive; a recent run's `pool` carries that key.

**Ranking.** A board is a category, a `sub` (`set` or `random`), the Deathless filter and a set of run types. Each player keeps their best run (lowest IGT, the earliest on a tie). Equal IGT shares a rank and the next rank skips (1, 2, 2, 4). With obsolete runs requested, every run of the board is listed by time and the runs that are not their player's best carry no rank. The record history lists, in date order, each run strictly faster than every earlier one; the web side words it like speedrun.com's history list (a new holder "set a new record time" and shows the gain on the previous record, a holder beating their own record "improved their time"). A recent run's place is its place on its category's Set Seed board (all run types, Deathless filter off): 1 + the number of other players whose best there is strictly faster. A recent run on a seed excluded from Set Seed has no place (`rank` null): that seed's runs are on no Set Seed board.

**Record seed.** A board response carries `record_seed`: the seed of its first ranked row (the record) and how many runs of the board, obsolete ones included, are on that seed. `null` on an empty board.

**Weapon** (the "Route" column, after speedrun.com's Elden Ring boards). The combo held for the most ticks over the run (summed `zone_history` weapon ticks, base ids), the same id coercion as `/weapons`. Runs from before weapon tracking have none. It is decoded only for the rows a response returns, never for the whole run list.

**The page.** `/speedrun` (header "Speedrun", `web/src/routes/speedrun/+page.svelte`, state in `web/src/lib/speedrun.ts`) mirrors its state into the URL so a board can be shared: `pool`, `sub=random` (Set Seed is the default and stays out), `deathless=1`, `types`, `obsolete=1`, `view`. The old `sub=any|deathless` values read as Set Seed. A board shows the category pills, then the "<Category> - Subcategories" segmented control (Set Seed / Random Seed), then the **WR seed band** (a gold-tinted strip: "WR seed" chip, the record's seed linking to its seed page focused on the record run, its time, the holder, a Blind or Replay chip and "N runs" from `record_seed`; absent when `record_seed` is null), then the toolbar. Filters lists Races, Daily Seeds, Event races, Solo runs, "Deathless only" and "Show obsolete runs". The **Run column** (Blind or Replay chip) shows on the Set Seed board only. A seed links through `speedrunSeedHref`: its seed page, focused on that run (see The web page below). A recent run of the side column reads "Blind" or "Replay", plus " · Deathless" for a deathless run, then its weapon.

**OBS overlay.** The "OBS overlay" button of the board toolbar opens a settings window that builds the URL of `/overlay/speedrun/<pool>`, a transparent leaderboard for an OBS Browser Source in the style of the race leaderboard overlay (badge in place of speedrun.com's flag, name template kept). It shows the board on screen, personal bests only (never obsolete runs): the category, `sub=random` for Random Seed (Set Seed is the default and stays out), `deathless=1` for the Deathless filter and the `types` filter, under the page's own parameter names. The settings window builds the URL from the board currently shown (its `sub` and `deathless`), and the overlay reads them to fetch the matching board. `top` rows (default 3) stay fixed from first place; `cycle` rows (default 3) page every 6 seconds through the players after them, up to rank `until` (default 20, players tied at that rank included); `player` (a Twitch username, matched whatever its case, prefilled with the viewer's own) pins that player's row at the bottom, set apart, with a gold time. A pinned player already in the top gets the gold time in place instead, and never also shows in the cycle; a player without a run on the board gets no row. Default values stay out of the URL. The overlay refetches the board every 5 minutes (every 30 seconds until a first load succeeds), so a new personal best shows once the stats cache has refreshed (up to about half an hour, as on the tab). The row split lives in `speedrunOverlayRows` (`web/src/lib/speedrun.ts`).

**Endpoints.** `GET /api/stats/speedrun` returns the categories, the run and player counts and the five most recent runs. `GET /api/stats/speedrun/{category}?sub=set|random&deathless=<bool>&types=<race,daily,event,solo>&obsolete=<bool>` returns one board, its record history and its record seed; `sub` defaults to `set` and anything else is 422, `types` must be a non-empty subset of the four (422 otherwise) and a category without counted runs answers 404. The seed page endpoints live under `/api/speedrun` (see Seed page below).

**Cache keys.** Both endpoints sit behind the stats cache; the counted run list itself is cached once (`speedrun:runs`, light columns only) and every board key (`speedrun:board:<category>:<sub>:<deathless>:<types>:<obsolete>`) derives from it. A board is cached as its serialized JSON bytes rather than a response model: with obsolete runs shown it lists thousands of rows, and one bytes object adds nothing to garbage-collection passes nor needs serializing on each hit. A Set Seed exclusion or its removal drops every `speedrun:` key at once (`forget_speedrun_caches` in `api/stats.py`), so the boards change without waiting for the TTL.

## Seed page

`GET /api/speedrun/seeds/{seed}` (router `api/speedrun.py`, rules in `services/set_seed_service.py`) serves the page of one played seed: its runs, its map, whether it can be replayed in Set Seed and what keeps its files.

**Which seeds have a page.** `{seed}` is the full seed number or a prefix of at least 6 characters (trimmed, any case). Only known seeds answer: not AVAILABLE, not from a training pool, with a race RUNNING or FINISHED on it or a solo session in `speedrun` or `set_seed` mode (any status). Any other seed answers 404 "Unknown seed" and never makes a prefix ambiguous, so no response reveals an unplayed seed. A prefix matching several known seeds answers 409 "Ambiguous seed ID". The protection and admin exclusion endpoints below take the seed the same way.

**Public.** A known seed's page is public once no blind run on it is in progress: no race whose mode is not `set_seed` in SETUP or RUNNING on it (Daily Seeds, event races and async races included), and no ACTIVE `speedrun` session. Set Seed races and sessions never hide a page. While a page is not public, it answers `public: false` with `graph_json` null, no runs and empty stats (`best_igt_ms` and `median_igt_ms` null, `runs` and `players` 0); the seed number, category, origin, statuses and viewer block stay.

**Replayable.** A public seed is replayable in Set Seed unless one of these holds. The first one that holds, in this order, gives `not_replayable_code` and `not_replayable_reason`:

| Code               | Reason                                           | When                                                                                                 |
| ------------------ | ------------------------------------------------ | ---------------------------------------------------------------------------------------------------- |
| `in_progress`      | `A blind run on this seed is still in progress.` | The page is not public.                                                                              |
| `excluded`         | `Excluded from Set Seed: <reason>`               | An admin excluded the seed (see Admin exclusion).                                                    |
| `old_game_version` | `Built for an older game version.`               | `Seed.created_at` (when the pool scan added the seed) is before `SET_SEED_MIN_SEED_DATE` (when set). |
| `old_category`     | `Built for an older version of <Pool>.`          | `total_layers` differs from the pool config's `layers_count`.                                        |
| `purged`           | `Files purged.`                                  | The seed's zip (`folder_path`) is gone.                                                              |

**Response.** `SpeedrunSeedResponse`:

- `category` and `category_name` come from `seed_category`: the pool's own at its current layer count, else `<pool>@<layers>` named `<Pool> (<n> layers)`, whether that count is archived or not. An old 25-layer Standard seed linked from an old race page still has its page, its runs and its name.
- `origin` is where the seed was first played: its earliest blind race (mode not `set_seed`, RUNNING or FINISHED, by start, else creation), with `race_id`, `race_name`, `daily_date` and `played_at`; without one, the earliest `speedrun` session's creation (race fields null); null when only replays were run on it.
- `runs` are every counted run on the seed (`load_counted_runs(seed_id=...)`: the board rules, plus layer counts missing from `archived_layers`), blind and replay, every run type, Deathless or not, excluded seed or not, by time. Each player's best run is ranked (shared ranks as on the boards) and their other runs have `rank` null. A row is a board row plus `run_type` and the run's `zone_history`, loaded for this seed's runs only.
- `stats` are the best time, the median time (the lower middle on an even count, so always a real run's time), the run count and the player count over those runs.
- `excluded_reason` is the admin's reason while the seed is excluded, `protected_by` the number of players protecting it, `pool_config` the pool's settings and `graph_json` the map (null while not public).
- `protectable` says whether a protection would keep the seed's files: false when `not_replayable_code` is `purged`, `old_game_version` or `old_category` (the files are gone, or the seed can never be replayed again), true otherwise, `excluded` and `in_progress` included (an admin may restore the seed; the blind runs end).

**Kept reasons.** `kept_reasons` lists why the seed's files are kept, in this order, each only when it holds:

1. `Seed of the current <Pool> pool`: the seed is not DISCARDED.
2. `Top <N> seed of <category name>`: among the `SET_SEED_KEPT_TOP_SEEDS` seeds of its category with the best times on the Set Seed board (`top_seed_numbers`, read from the cached `speedrun:runs`, so it can lag by one cache TTL). Seeds excluded from Set Seed still rank here, though the board drops them: an admin may restore one, and a purged zip cannot be rebuilt.
3. `Protected by <n> player`, or `players` from 2 on.
4. `Played in the last <D> days`: the latest race (finish, else start, else creation) or solo session (finish, else creation) on the seed, of any mode and status, is less than `SEED_PURGE_GRACE_DAYS` days old, or the seed is in use now (a race in SETUP or RUNNING, or an ACTIVE solo session, on it, however old).

`retention_reasons` builds them from the facts `load_retention_facts` loads for any number of seeds at once. An empty list means nothing keeps a DISCARDED seed's files.

**Protection.** `PUT /api/speedrun/seeds/{seed}/protection` (logged in, not banned) keeps a seed's files: never on a seed that is not `protectable` (409 with its `not_replayable_reason`, e.g. "Files purged."), only by a player with a finished run on the seed, a FINISHED participant of a FINISHED race of any mode or a FINISHED `speedrun` or `set_seed` solo session (403 "Only players with a finished run on this seed can protect it"), at most `SEED_PROTECTION_LIMIT` seeds per player (409 "You already protect 3 seeds", with the setting's value: "1 seed" for a limit of 1), with no expiry. Protecting a seed already protected answers 200 and takes no second slot. `DELETE` on the same path removes the protection and frees the slot (idempotent too). Both answer the viewer block. Protections live in `seed_protections`, one row per player and seed.

**Viewer.** The page's `viewer` is null for a logged-out visitor; otherwise `can_protect` (the viewer has a finished run on the seed, as the protection rule counts it, and is not banned, whatever their quota or the seed's `protectable`), `protected`, `protected_seeds` (the seed numbers the viewer protects, oldest protection first) and `protection_limit`.

**Admin exclusion.** `PUT /api/admin/seeds/{seed}/set-seed-exclusion` with `{"reason": "..."}` (1 to 500 characters, trimmed; 422 otherwise) excludes a seed from Set Seed: it is no longer replayable, its runs leave the Set Seed boards and stay on Random Seed, and the page shows `excluded_reason`. The time, the reason and the admin are stored on the seed (`set_seed_excluded_at`, `set_seed_excluded_reason`, `set_seed_excluded_by_id`); excluding it again replaces them. `DELETE` on the same path lifts the exclusion. Both answer 204 and drop the speedrun caches, so the boards change at once.

**Caching.** The seed page is not cached, so a finished solo run, a protection or an exclusion shows at once; only its top-seed reason reads the cached run list.

**The web page.** `/speedrun/seed/<seed_number>` (`web/src/routes/speedrun/seed/[seed]/`, components `Seed*.svelte` in `web/src/lib/components/stats/speedrun/`) loads the endpoint above; an unknown seed shows the site's not-found page ("Seed not found"), an ambiguous prefix the same page asking for more of the seed ID, and any other failure the error page. It reuses the finished race page's layout (fixed-height, the runs rail stacked above the map on phones), without Highlights or chat:

- **Runs on this seed**, the left rail: the race page's `Leaderboard` in finished mode, one row per run in time order (keyed by `run_id`, colored by position), with a Blind or Replay chip (its `runKinds` prop), the death count and the loadout. Rows show the server's `rank` (its `ranks` prop), not their position: equal times share a place, and a player's slower runs have none and are dimmed like the boards' obsolete rows. A click ticks one run (its path alone on the map), Ctrl+click compares several, as on race pages. `?run=<run_id>` ticks that run on arrival; an id that is not listed ticks nothing. A public seed without a counted run (only `normal` races on it) says "No ranked run on this seed yet." and still shows its map.
- **Header**: "Seed <n>", then "<category name> · first played in <origin race> on <date>" (the race or the day linked) or "first played solo on <date>", the share button and the status chip, "Replayable" or "Not replayable". The chip's tooltip (hover, or keyboard focus) gives the reason when the seed is not replayable; otherwise "Files kept" and the kept reasons joined by " · ", or "Files may be purged. Protect this seed to keep them." when nothing keeps them.
- **Play this seed in Set Seed**, the card in place of the race rules card: how replays count ("<category name> · Set Seed" board, never Random Seed), and the reason when the seed is not replayable. Below a divider, for a logged-in viewer only: "Protect this seed" with the quota ("You protect <k> of your <limit> seeds.") and a Protect or Unprotect button; a seed that is not `protectable` gets "Protection only keeps the files of a replayable seed." instead (a viewer who already protects it keeps Unprotect, to free the slot), a viewer without a finished run "Only players who finished a run on this seed can protect it.", and at the limit the button is disabled and the viewer's protected seeds are listed as links. A protection reloads the seed, so the chip's kept reasons follow.
- The Map / Replay toggle (`MetroDagFull` with the layer comparison under it, `RaceReplay`), the stats row (best time, median time, runs with the replay count, players) and the category card (`PoolSettingsCard`).
- **Admins** get a reason field and "Exclude from Set Seed", or, on an excluded seed, "Excluded from Set Seed: <reason>" and "Restore"; the page reloads the seed after either.
- **Not public**: the header and its chip, and "This seed's map opens once every blind run on it is over." in place of the rail and the map.

Links to the page come from `web/src/lib/speedrun.ts`: `seedPageHref(seed, runId?)` builds it (`?run=` when a run is given); `speedrunSeedHref(run)` is a board run's seed page focused on that run; `raceSeedPageHref` (a finished race, or a Set Seed race at any status) and `sessionSeedPageHref` (a Set Seed session, or a Speedrun session no longer active; never a `normal` session) say when a race or solo page should link its seed. They only spare links to pages that would still be hidden: the server's public rule stays the guard. Race and session responses carry `mode` on the web types too (`RunMode`).

Where the links appear: the WR seed band (the seed number and an "Open seed" button, both to the record run's page), the board table (the seed cell is the keyboard-reachable link; a click anywhere else on a row navigates to the same page through `goto`, except on the player link or any other link or button, with Ctrl, Cmd or Shift held, or when it ends a text selection), the record history's times, and the `Seed <n>` badge of the race, daily and solo session pages, which is a link only when `raceSeedPageHref` / `sessionSeedPageHref` return one (a running blind race or an active Speedrun session shows plain text). The seed status chip's tooltip opens on hover and on focus (so a tap shows it on a phone) and Escape blurs the chip to close it.

## Settings

Env settings in `server/speedfog_racing/config.py`, listed in `server/.env.example`:

| Setting                   | Default | Meaning                                                                                                                                                                  |
| ------------------------- | ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `SET_SEED_MIN_SEED_DATE`  | unset   | Seeds added (scanned) before this instant are not replayable (`old_game_version`). Raised by hand after a game patch that breaks older seeds; unset disables the cutoff. |
| `SET_SEED_KEPT_TOP_SEEDS` | 10      | How many of each category's best Set Seed seeds keep their files (the `Top <N> seed` reason).                                                                            |
| `SEED_PROTECTION_LIMIT`   | 3       | Seeds a player can protect at once.                                                                                                                                      |
| `SEED_PURGE_GRACE_DAYS`   | 30      | Days a seed keeps its files after its last race or session (the `Played in the last <D> days` reason).                                                                   |

**Purge.** `deploy/cleanup-seeds.sh` deletes a DISCARDED seed's zip only when these settings allow it (top seed, protected, recently played or in use, or added before the cutoff); see the retention section of `docs/SEED_PIPELINE.md`.

**Deploy.** The first production value of `SET_SEED_MIN_SEED_DATE` is `2026-09-01T00:00:00Z`, when the pools were regenerated for Elden Ring 1.17: earlier seeds carry a 1.16 `regulation.bin` that breaks Torrent on the 1.17 executable. Set it in the server's `.env` when this ships.
