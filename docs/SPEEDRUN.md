# speedrun.fog

The `speedrun.fog` tab of `/stats` is a parody of a speedrun.com game page: the same layout (game header card, category pills, subcategories, ranking table, side column with game stats and recent runs) in SpeedFog's colors. It carries no competitive value, since times on different seeds do not compare; the point is recognising the layout.

Each category (a pool) has two boards, **Set Seed** and **Random Seed**, plus a **Deathless** filter. Computed in `services/speedrun_service.py`, served by `api/stats.py`.

**Which runs are counted.** A participant with status FINISHED in a race that has a seed and is itself FINISHED, whose user is not banned. Races flagged `exclude_from_stats` stay out, except Daily Seeds and event races (qualifiers and playoff races), which count. Public and private races both count. Pools whose config `type` is `training` never appear. Finished solo sessions in `speedrun` or `set_seed` mode (`TrainingSession.mode`) also count, as run type `solo`, under the same pool and layer-count rules; practice sessions never do. A run is `blind` unless it is a Set Seed replay (a race with `Race.set_seed` or a `set_seed` session), the runner having known the seed beforehand. Only seeds at the pool config's current `layers_count` count (a seed with another `total_layers` stays out), which stands in for "the current version of the pool": seeds generated before the fixed layer counts of May 2026 varied in depth (Standard ran from 17 to 38 layers), so most of them drop out, though an old seed that landed on the current count still counts. Changing a pool's layer count restarts its board, like a new game version on speedrun.com. A pool whose config has no `layers_count` keeps every seed. Requiring a finished race keeps a running Daily Seed or an open qualifier out until it ends, so the board never reveals the deaths or weapons a running daily hides.

**What each board counts.**

| Board       | Counts                                                                                                                                                       |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Set Seed    | Every counted run: blind and replay runs, of every run type (`race`, `daily`, `event`, `solo`).                                                              |
| Random Seed | Blind runs only: runs whose seed the runner did not know beforehand (not `Race.set_seed`, not a `set_seed` session). Empty when a category only has replays. |

A run's `blind` flag is exposed on every row, so a Set Seed board can mark which runs were blind. The Deathless filter (`deathless=true`) keeps only runs of races with the deathless option (`Race.deathless`) and so never includes solo runs. It combines with either board. The default boards include deathless races.

**Categories.** One per pool with at least one counted run: enabled pools by `sort_order` (pools without one last), then disabled (retired) pools in the same order. A category's `released_at` is its earliest seed at the current layer count (any seed without `layers_count`); the History list opens with it ("Boss Rush was released"). The category key of a board is the pool name for now.

**Ranking.** A board is a category, a `sub` (`set` or `random`), the Deathless filter and a set of run types. Each player keeps their best run (lowest IGT, the earliest on a tie). Equal IGT shares a rank and the next rank skips (1, 2, 2, 4). With obsolete runs requested, every run of the board is listed by time and the runs that are not their player's best carry no rank. The record history lists, in date order, each run strictly faster than every earlier one; the web side words it like speedrun.com's history list (a new holder "set a new record time" and shows the gain on the previous record, a holder beating their own record "improved their time"). A recent run's place is its place on its category's Set Seed board (all run types, Deathless filter off): 1 + the number of other players whose best there is strictly faster.

**Record seed.** A board response carries `record_seed`: the seed of its first ranked row (the record) and how many runs of the board, obsolete ones included, are on that seed. `null` on an empty board.

**Weapon** (the "Route" column, after speedrun.com's Elden Ring boards). The combo held for the most ticks over the run (summed `zone_history` weapon ticks, base ids), the same id coercion as `/weapons`. Runs from before weapon tracking have none. It is decoded only for the rows a response returns, never for the whole run list.

**OBS overlay.** The "OBS overlay" button of the board toolbar opens a settings window that builds the URL of `/overlay/speedrun/<pool>`, a transparent leaderboard for an OBS Browser Source in the style of the race leaderboard overlay (badge in place of speedrun.com's flag, name template kept). It shows the board on screen, personal bests only (never obsolete runs): the category, `sub=deathless` for Deathless and the `types` filter, under the tab's own parameter names. `top` rows (default 3) stay fixed from first place; `cycle` rows (default 3) page every 6 seconds through the players after them, up to rank `until` (default 20, players tied at that rank included); `player` (a Twitch username, matched whatever its case, prefilled with the viewer's own) pins that player's row at the bottom, set apart, with a gold time. A pinned player already in the top gets the gold time in place instead, and never also shows in the cycle; a player without a run on the board gets no row. Default values stay out of the URL. The overlay refetches the board every 5 minutes (every 30 seconds until a first load succeeds), so a new personal best shows once the stats cache has refreshed (up to about half an hour, as on the tab). The row split lives in `speedrunOverlayRows` (`web/src/lib/speedrun.ts`).

**Endpoints.** `GET /api/stats/speedrun` returns the categories, the run and player counts and the five most recent runs. `GET /api/stats/speedrun/{category}?sub=set|random&deathless=<bool>&types=<race,daily,event,solo>&obsolete=<bool>` returns one board, its record history and its record seed; `sub` defaults to `set` and anything else is 422, `types` must be a non-empty subset of the four (422 otherwise) and a category without counted runs answers 404.

**Cache keys.** Both endpoints sit behind the stats cache; the counted run list itself is cached once (`speedrun:runs`, light columns only) and every board key (`speedrun:board:<category>:<sub>:<deathless>:<types>:<obsolete>`) derives from it. A board is cached as its serialized JSON bytes rather than a response model: with obsolete runs shown it lists thousands of rows, and one bytes object adds nothing to garbage-collection passes nor needs serializing on each hit.
